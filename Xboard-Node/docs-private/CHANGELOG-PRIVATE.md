# Private Changelog

## 2026-10-09 Installer replacement and management menu

- DISCOVERED: reinstall previously passed the old config/credentials into `xbctl config init`, appending a different machine rather than disconnecting the previous bindings. This could produce duplicate `health_port: 65530` entries and startup failure. A prior report's 401 still indicates an invalid/deleted/rotated machine credential; replacement cannot repair that old credential.
- Changed the maintained source installer and `node-installer/install.sh` mirror: installation generates a fresh current-format single target, privately backs up existing active files, stops only `xboard-node.service`, archives the old instance tree, then replaces the binding. Explicit stop failure or unsafe/custom paths refuse replacement. No panel records, collector data, external certificates or unrelated processes are deleted.
- Installer menu is now `1 install / 2 uninstall / 0 exit`, including parameterized panel commands; reads use a separate controlling-terminal FD. Automation requires `--yes`. Existing bindings need exact `REPLACE` confirmation; uninstall needs `UNINSTALL` unless explicitly automated.
- Added the lowercase `/usr/local/bin/node` management wrapper: `1 upgrade / 2 restart / 3 uninstall / 0 exit`. It uses sudo for non-root callers. Installation refuses an existing foreign `node` command, including Node.js, and foreign `xbctl` links. Upgrade fetches the maintained script, preserves config/credentials/instance files and health-port zero, and never implicitly reuses binaries in the SSH working directory.
- Backups use unique `backups/recovery-*` directories with mode `700`. Uninstall retains them even with `--purge`. Rollback explicitly checks file restoration, restores original service activity/enablement and command ownership, and reports recovery failure without restarting partially restored files. Pure upgrade keeps compatible legacy config and old installation metadata; it does not rebuild invalid multi-instance layouts.
- VERIFICATION: isolated Bash/filesystem and actual local `xbctl` configuration fixtures are recorded in the Node README. NOT RUN: real Linux/systemd installation, cgroup/port cleanup, controlling-terminal pipeline acceptance, production deployment and deliberately skipped client traffic. Immutable v1.13-orphan.2 Release assets remain unchanged.
